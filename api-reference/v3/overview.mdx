---
title: 'v3 Overview'
description: 'Legacy cursor-paginated Polymarket API for existing integrations.'
---

API v3 remains available for existing Polymarket integrations. New integrations should use [API v4](/api-reference/v4/overview), which returns to the simpler v2-style URL, pagination, and response conventions.

## Legacy v3 shape

| | v3 | v4 |
|---|---|---|
| **Coin** | `/v3/{coin}/...` path segment | required `?coin=` query parameter |
| **Pagination** | `limit` + `cursor` | `limit` + `offset` |
| **Response** | `{ data, pagination?, meta }` | named resources such as `{ markets: [...] }` |
| **Timestamps** | millisecond epoch or ISO-8601 inputs | millisecond epoch integers everywhere |
| **Errors** | nested `error` and `meta` objects | flat `{ error, code, request_id, details? }` |

## Authentication

Pass your key as `X-API-Key` or `Authorization: Bearer …`.

```bash
curl 'https://api.polybacktest.com/v3/btc/markets?limit=50' \
  -H "X-API-Key: $POLY_KEY"
```

## Pagination

Pass `pagination.next_cursor` from one response as `?cursor=` on the next request. Stop when `pagination.has_more` is `false`.

## Moving to v4

1. Change `/v3/btc/markets` to `/v4/markets?coin=btc`.
2. Replace cursor handling with `offset=response.next_offset`.
3. Read `markets` or `snapshots` instead of `data`.
4. Send and expect epoch-millisecond timestamps only.
5. Read errors from top-level `error`, `code`, and `request_id`.

v3 batch requests have no v4 equivalent; send the contained GET requests individually.
