API v3 is a clean rewrite of the v2 surface area. Same data, same auth, new ergonomics.

## What changed at a glance

| | v2 | v3 |
|---|---|---|
| **Coin** | `?coin=btc` query param | `/v3/{coin}/...` path segment |
| **Pagination** | `limit` + `offset` (`OFFSET N`) | `limit` + `cursor` (keyset/seek) |
| **Total count** | Always in response | Opt-in via `?include_count=true` |
| **Response shape** | Endpoint-specific (`{ markets: [...] }`, `{ snapshots: [...] }`) | Uniform `{ data, pagination?, meta }` envelope |
| **Errors** | `{ "error": "string" }` | `{ "error": { "code", "message", "details" }, "meta" }` |
| **Batch** | — | `POST /v3/batch` (up to 10 GETs) |

## Base URLs

- **`https://api.polybacktest.com`** — everyone (free, pro, enterprise)
- **`https://enterprise.polybacktest.com`** — exclusive endpoint for enterprise plan API keys (non-enterprise keys are rejected with `ENTERPRISE_ONLY`)

Enterprise users can use either URL — routing is decided by the API key, not the hostname. The enterprise domain just gives organizations a distinct, premium base URL for their integrations.

## Response envelope

Every successful response follows one of two shapes.

### Single resource

```json
{
  "data": { "market_id": "1051520", "market_type": "5m", "...": "..." },
  "meta": {
    "request_id": "req_a1b2c3d4e5f6",
    "timestamp": "2026-04-16T12:00:00Z"
  }
}
```

### Paginated list

```json
{
  "data": [ { "market_id": "1051520", "...": "..." } ],
  "pagination": {
    "next_cursor": "eyJzdCI6IjIwMjYtMDQtMTVUMjM6NTU6MDBaIiwiaWQiOiIxMDUxNTIwIn0",
    "has_more": true,
    "limit": 50,
    "count": 50
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-04-16T12:00:00Z" }
}
```

`pagination.total_count` is **omitted by default**. To opt in (at the cost of a `COUNT(*)`), pass `?include_count=true`.

### Error

```json
{
  "error": {
    "code": "RATE_LIMIT_BURST",
    "message": "Burst limit exceeded. Max 10 requests per second.",
    "details": { "retry_after": 1, "limit": 10, "window": "second" }
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-04-16T12:00:00Z" }
}
```

The HTTP status is set per the error `code` (see [Error Codes](/api-reference/v3/error-codes)).

## Cursor pagination

Cursors are opaque base64url-encoded sort-key snapshots. To paginate forward, take the `pagination.next_cursor` from one response and pass it as `?cursor=` in the next request:

```bash
# Page 1
curl 'https://api.polybacktest.com/v3/btc/markets?type=5m&limit=50' \
  -H "X-API-Key: $POLY_KEY"

# Page 2 — pass the cursor from page 1's pagination.next_cursor
curl 'https://api.polybacktest.com/v3/btc/markets?type=5m&limit=50&cursor=eyJzdCI...' \
  -H "X-API-Key: $POLY_KEY"
```

Stop paginating when `pagination.has_more === false`.

<Note>
Compared to v2's `OFFSET N`, cursor pagination stays O(1) at any depth and uses the same DB indexes. Old `?offset=N` is still accepted for back-compat but is marked deprecated.
</Note>

## Authentication

Same as v2 — pass your key as `X-API-Key` or `Authorization: Bearer …`.

```bash
curl 'https://api.polybacktest.com/v3/btc/markets' -H "X-API-Key: $POLY_KEY"
```

## Migration from v2

The mechanical changes are usually:

1. Move the `?coin=` query param into the path: `/v2/markets?coin=btc` → `/v3/btc/markets`.
2. Replace `?offset=` with cursor pagination (or keep using `?offset=` while you migrate — it still works).
3. Read your data from `response.data` instead of `response.markets` / `response.snapshots` / `response.trades`.
4. If you depended on `total`, opt in via `?include_count=true` only where you actually need it.

v2 will continue to serve traffic through its sunset window; responses include `Sunset` and `Deprecation` headers and a `Link` to this v3 documentation.
