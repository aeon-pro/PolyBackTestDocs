## API Rate Limits

To ensure fair usage and system stability, PolyBackTest enforces per-user rate limits that vary by plan. Limits are applied per user, not per API key - using multiple keys does not increase your quota.

### Rate Limits by Plan

| Plan | Requests per Second | Requests per Minute |
| :--- | :--- | :--- |
| **Free** | 1 | - |
| **Pro** | 10 | 300 |
| **Enterprise** | Custom | Custom |

<Info>
  Free-plan users are limited to **1 request per second**. Pro users can burst to **10 requests per second** with a sustained **300 requests per minute**. Enterprise plans ship with custom limits agreed per contract - see your plan details in the [Dashboard](https://polybacktest.com/dashboard?tab=billing).
</Info>

### Rate Limit Headers

Every API response includes rate limit headers so you can track your usage:

- `X-RateLimit-Limit` - your maximum allowed requests for the current window.
- `X-RateLimit-Remaining` - requests remaining in the current window.

When rate limited, a `Retry-After` header indicates how many seconds to wait before retrying.

### 429 Too Many Requests

v4 error responses include a stable top-level `code` so you can branch on burst vs. sustained:

```json
{
  "error": "Burst limit exceeded. Max 10 requests per second.",
  "code": "RATE_LIMIT_BURST",
  "request_id": "req_a1b2c3d4e5f6",
  "details": { "retry_after": 1, "limit": 10, "window": "second" }
}
```

```json
{
  "error": "Rate limit exceeded. Max 300 requests per minute.",
  "code": "RATE_LIMIT_SUSTAINED",
  "request_id": "req_a1b2c3d4e5f6",
  "details": { "retry_after": 47, "limit": 300, "window": "minute" }
}
```

## Historical Data Limits

Historical access is separate from request rate limits. PolyBackTest stores up to 60 days of Polymarket crypto data, but each API key can only query the history window included in its plan.

| Plan / Add-on | Historical Data Window |
| :--- | :--- |
| **Free** | 31 days |
| **Pro** | 31 days by default |
| **Pro + 60-day history** | 60 days |
| **90-day history** | Reserved for a future add-on |
| **Dedicated / Enterprise** | 60 days |

When `start_time` is omitted on list endpoints, the API automatically clamps the query to the oldest timestamp your plan can access. When you provide an explicit `start_time` or point-in-time timestamp before your allowed window, v4 endpoints return `403 HISTORY_LIMIT_EXCEEDED`.

```json
{
  "error": "Your plan only allows 31 days of history.",
  "code": "HISTORY_LIMIT_EXCEEDED",
  "request_id": "req_a1b2c3d4e5f6",
  "details": {
    "field": "start_time",
    "max_history_days": 31,
    "oldest_allowed": 1779441600000
  }
}
```

<Info>
The 31/60-day history entitlement is enforced on Polymarket market and snapshot endpoints. Dedicated/Enterprise plans receive the 60-day window.
</Info>

## Coin Access by Plan

ETH and SOL data is available to **Pro** and **Enterprise** users. Free-plan users can only query BTC. Attempting `?coin=eth` or `?coin=sol` on a free plan returns an access error:

```json
{
  "error": "ETH data requires a Pro plan or enterprise access",
  "code": "COIN_NOT_IN_PLAN",
  "request_id": "req_a1b2c3d4e5f6",
  "details": { "coin": "eth" }
}
```

## Plan-Based Market Limits

Access to market data depends on your plan. Free-plan users can access a limited window of the **most recent** BTC markets for each timeframe. Pro users can access all included markets within their purchased historical-data window.

### Free Plan Limits

| Market Type | Latest Markets Accessible | Snapshots |
| :--- | :--- | :--- |
| **5m** | 50 | Unlimited (for accessible markets) |
| **15m** | 50 | Unlimited (for accessible markets) |
| **1h** | 24 | Unlimited (for accessible markets) |
| **4h** | 24 | Unlimited (for accessible markets) |
| **24h** | 5 | Unlimited (for accessible markets) |

<Info>
  **"Latest"** means the most recently created markets, sorted by start time. As new markets are created, older ones rotate out of the free-plan window.
</Info>

### What Does This Mean?

- **List Markets (`GET /v4/markets?coin=...`)** - free users only see markets within their market-count and history windows. Results outside the allowed window are filtered out.
- **Get Market by ID/Slug** - accessing a market outside the free-plan market window returns `402 PLAN_UPGRADE_REQUIRED`; a market older than the applicable history window returns `403 HISTORY_LIMIT_EXCEEDED`.
- **Snapshots** - users can access snapshots for markets within their plan window. A market outside the free-plan market window returns `402`; an explicit timestamp older than the history entitlement returns `403 HISTORY_LIMIT_EXCEEDED`.

### Check Your Limits

Your plan, included markets, and (for enterprise) infrastructure routing are visible in the [Dashboard](https://polybacktest.com/dashboard?tab=billing). The `X-RateLimit-Limit` and `X-RateLimit-Remaining` response headers on every authenticated request also reflect the limits the gateway is currently applying to your key.

### Handling Plan Errors

When your request needs a higher plan, v4 returns `402`:

```json
{
  "error": "Free plan access exhausted for this filter. Upgrade for higher market limits.",
  "code": "PLAN_UPGRADE_REQUIRED",
  "request_id": "req_a1b2c3d4e5f6",
  "details": {
    "current_plan": "free",
    "required_plan": "pro",
    "market_type": "5m"
  }
}
```

<Tip>
  Branch on `code` (stable), not `error` (may change). Full list: [v4 Error Codes](/api-reference/v4/error-codes).
</Tip>
