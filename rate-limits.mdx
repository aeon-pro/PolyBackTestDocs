## API Rate Limits

To ensure fair usage and system stability, the PolyBackTest API implements rate limiting on a per-key basis.

| Limit Type | Value | Description |
| :--- | :--- | :--- |
| **Standard Rate** | 2000 requests/minute | The baseline limit for all API keys. |
| **Burst Limit** | 100 requests/second | Allows for short bursts of high-volume traffic. |

If you exceed these limits, the API will return a `429 Too Many Requests` error. The response headers will include details about your current usage and when the limit will reset:

- `X-RateLimit-Limit`: Your total request limit per minute.
- `X-RateLimit-Remaining`: The number of requests you have left in the current window.
- `X-RateLimit-Reset`: The time at which the current window resets.

We maintain an extensive database of historical prediction market data to support your backtesting needs.

- **Retention Period**: Data is stored for the past **31 days**.
- **Market Coverage**: Over **5000+ markets** specifically tracked.
- **Data Volume**: Access to over **60 million+ snapshots** across various timeframes.

## Data Sources & Accuracy

### Bitcoin Price
The BTC price data used in our system is sourced directly from **Binance**.

### Market Resolution
For **5-minute** and **15-minute** markets, PolyBackTest aligns with **Polymarket**, which uses **Chainlink** as its oracle for resolution. 

<Note>
  Because we source BTC price data from Binance while Polymarket uses Chainlink for settlement, you might observe slight discrepancies between the live BTC price shown in our API/snapshots and the price displayed on the Polymarket website.
</Note>

**Importantly:**
- **Orderbooks**: Are captured directly from the market and are consistent.
- **Resolution Data**: We use the official resolution data, so settlement outcomes are accurate.
- **Impact**: This slight price variance does not affect the integrity of orderbook depth or market resolution status.
