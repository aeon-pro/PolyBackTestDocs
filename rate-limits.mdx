## API Rate Limits

To ensure fair usage and system stability, PolyBackTest enforces per-user rate limits that vary by plan. Limits are applied per user, not per API key - using multiple keys does not increase your quota.

### Rate Limits by Plan

| Plan | Requests per Second | Requests per Minute |
| :--- | :--- | :--- |
| **Free** | 1 | - |
| **Pro** | 10 | 300 |
| **Enterprise** | Custom | Custom |

<Info>
  Free-plan users are limited to **1 request per second**. Pro users can burst to **10 requests per second** with a sustained **300 requests per minute**. Enterprise plans ship with custom limits agreed per contract - see your plan details in the [Dashboard](https://polybacktest.com/dashboard?tab=billing).
</Info>

### Rate Limit Headers

Every API response includes rate limit headers so you can track your usage:

- `X-RateLimit-Limit` - your maximum allowed requests for the current window.
- `X-RateLimit-Remaining` - requests remaining in the current window.

When rate limited, a `Retry-After` header indicates how many seconds to wait before retrying.

### 429 Too Many Requests

v3 error responses include a stable `error.code` so you can branch on burst vs. sustained:

```json
{
  "error": {
    "code": "RATE_LIMIT_BURST",
    "message": "Burst limit exceeded. Max 10 requests per second.",
    "details": { "retry_after": 1, "limit": 10, "window": "second" }
  },
  "meta": { "request_id": "req_a1b2c3d4e5f6", "timestamp": "2026-04-16T12:00:00Z" }
}
```

```json
{
  "error": {
    "code": "RATE_LIMIT_SUSTAINED",
    "message": "Rate limit exceeded. Max 300 requests per minute.",
    "details": { "retry_after": 47, "limit": 300, "window": "minute" }
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-04-16T12:00:00Z" }
}
```

## Historical Data Limits

Historical access is separate from request rate limits. PolyBackTest stores up to 60 days of Polymarket crypto and Binance data, but each API key can only query the history window included in its plan. Equity markets are Pro-only and always use a fixed 31-day history window.

| Plan / Add-on | Historical Data Window |
| :--- | :--- |
| **Free** | 31 days |
| **Pro** | 31 days by default |
| **Pro + 60-day history** | 60 days |
| **90-day history** | Reserved for a future add-on |
| **Equity markets** | 31 days fixed |
| **Enterprise** | Contract-specific for Polymarket crypto/Binance; equity fixed at 31 days |

When `start_time` is omitted on list endpoints, the API automatically clamps the query to the oldest timestamp your plan can access. When you provide an explicit `start_time` or point-in-time timestamp before your allowed window, v3 endpoints return `403 HISTORY_LIMIT_EXCEEDED`.

```json
{
  "error": {
    "code": "HISTORY_LIMIT_EXCEEDED",
    "message": "Your plan only allows 31 days of history.",
    "details": {
      "field": "start_time",
      "max_history_days": 31,
      "oldest_allowed": "2026-04-22T12:00:00+00:00"
    }
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-05-23T12:00:00Z" }
}
```

<Info>
The 31/60-day history entitlement is enforced on Polymarket crypto market/snapshot endpoints and Binance spot/futures snapshot and trade endpoints. Equity market endpoints remain fixed at 31 days even when the key has the 60-day history add-on.
</Info>

## Coin & Symbol Access by Plan

ETH and SOL data is available to **Pro** and **Enterprise** users. Free-plan users can only query BTC. Attempting `/v3/eth/...` or `/v3/sol/...` on a free plan returns `402`:

```json
{
  "error": {
    "code": "COIN_NOT_IN_PLAN",
    "message": "ETH data requires a Pro plan or enterprise access",
    "details": { "coin": "eth" }
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-04-16T12:00:00Z" }
}
```

**All equity symbols** (`spx`, `spx-open`, `spy`, `wti`, `xauusd`) are Pro-only. Free-plan calls to `/v3/equity/{symbol}/...` are rejected at the gateway with the same `COIN_NOT_IN_PLAN` shape (with `details.symbol` set instead of `details.coin`).

## Plan-Based Market Limits

Access to market data depends on your plan. Free-plan users can access a limited window of the **most recent** BTC markets for each timeframe. Pro users can access all included markets within their purchased historical-data window.

### Free Plan Limits

| Market Type | Latest Markets Accessible | Snapshots |
| :--- | :--- | :--- |
| **5m** | 50 | Unlimited (for accessible markets) |
| **15m** | 50 | Unlimited (for accessible markets) |
| **1h** | 24 | Unlimited (for accessible markets) |
| **4h** | 24 | Unlimited (for accessible markets) |
| **24h** | 5 | Unlimited (for accessible markets) |

### Equity Symbols (Pro only)

| Symbol | Free | Pro / Enterprise |
| :--- | :--- | :--- |
| `spx`, `spx-open`, `spy`, `wti`, `xauusd` | No access (`403`) | Unlimited markets, snapshots, and underlying-price ticks inside the fixed 31-day history window |

<Info>
  **"Latest"** means the most recently created markets, sorted by start time. As new markets are created, older ones rotate out of the free-plan window.
</Info>

### What Does This Mean?

- **List Markets (`GET /v3/{coin}/markets`)** - free users only see markets within their market-count and history windows. Results outside the allowed window are filtered out.
- **Get Market by ID/Slug** - accessing a market outside the free-plan market window returns `402 PLAN_UPGRADE_REQUIRED`; a market older than the applicable history window returns `403 HISTORY_LIMIT_EXCEEDED`.
- **Snapshots** - users can access snapshots for markets within their plan window. A market outside the free-plan market window returns `402`; an explicit timestamp older than the history entitlement returns `403 HISTORY_LIMIT_EXCEEDED`.

### Check Your Limits

Your plan, included markets, and (for enterprise) infrastructure routing are visible in the [Dashboard](https://polybacktest.com/dashboard?tab=billing). The `X-RateLimit-Limit` and `X-RateLimit-Remaining` response headers on every authenticated request also reflect the limits the gateway is currently applying to your key.

### Handling Plan Errors

When your request needs a higher plan, v3 returns `402`:

```json
{
  "error": {
    "code": "PLAN_UPGRADE_REQUIRED",
    "message": "Free plan access exhausted for this filter. Upgrade for higher market limits.",
    "details": {
      "current_plan": "free",
      "required_plan": "pro",
      "market_type": "5m"
    }
  },
  "meta": { "request_id": "req_...", "timestamp": "2026-04-16T12:00:00Z" }
}
```

<Tip>
  Branch on `error.code` (stable), not `error.message` (may change). Full list: [v3 Error Codes](/api-reference/v3/error-codes).
</Tip>
