## Overview

PolyBackTest uses API keys to authenticate requests. You can view and manage your API keys in the [Dashboard](https://polybacktest.com/dashboard).

Your API keys carry many privileges, so be sure to keep them secure! Do not share your secret API keys in publicly accessible areas such as GitHub, client-side code, and so forth.

## Generate an API Key

1. Log in to your [PolyBackTest account](https://polybacktest.com/login).
2. Navigate to the [Dashboard](https://polybacktest.com/dashboard).
3. Select the **API Keys** tab from the sidebar.
4. Click the **Create New Key** button.
5. Enter a name for your key (e.g., "Production Bot") and set an expiration if desired.
6. Click **Create Key**.
7. **Copy your key immediately.** It will only be shown once.

<Note>
  If you lose your API key, you will need to revoke it and generate a new one. We do not store the full key for security reasons.
</Note>

## Using the API Key

You must include the API key in the `Authorization` header (as a Bearer token) or the `X-API-Key` header with every request.

### Header Example

```bash
# Using Authorization header (recommended)
curl "https://api.polybacktest.com/v3/btc/markets" \
  -H "Authorization: Bearer pdm_your_api_key_here"

# Or using X-API-Key header
curl "https://api.polybacktest.com/v3/btc/spot/latest" \
  -H "X-API-Key: pdm_your_api_key_here"
```

<Info>
v3 puts the coin in the URL path (`/v3/{coin}/...`). Supported coins: `btc`, `eth`, `sol`. Each request targets exactly one coin.
</Info>

### Base URLs

| Domain | Who can use it |
| :--- | :--- |
| `api.polybacktest.com` | Everyone (free, pro, enterprise). |
| `enterprise.polybacktest.com` | Enterprise plan keys only - non-enterprise keys are rejected with `ENTERPRISE_ONLY`. |

Enterprise users can use either URL - routing is decided by the API key, not the hostname.

### Authentication Errors

v3 error responses use a stable machine-readable `code` (see [v3 Error Codes](/api-reference/v3/error-codes)):

| `error.code` | Status | When |
| :--- | :--- | :--- |
| `AUTH_MISSING` | `401` | No API key was provided. |
| `AUTH_INVALID` | `401` | The key is unknown, revoked, or malformed. |
| `AUTH_EXPIRED` | `401` | The key is past its expiration date. |
| `ENTERPRISE_ONLY` | `403` | A non-enterprise key was used on the `enterprise.` domain. |

## Best Practices

- **Use distinct keys**: Create separate API keys for different applications or environments (e.g., development vs. production).
- **Set expirations**: For added security, set expiration dates on your keys and rotate them periodically.
- **Revoke unused keys**: Delete keys that are no longer in use to reduce your attack surface.
