<Note>
This guide uses **API v4**, the recommended API for new integrations. Its request and response shape stays close to v2: `coin` is a query parameter, lists have named arrays, and pagination uses `limit` plus `offset`.
</Note>

## Timestamps

Every v4 timestamp is a Unix epoch integer in **milliseconds**.

```text
2026-05-01T00:00:00Z  →  1777593600000
```

This rule applies to:

- `start_time` and `end_time` query parameters
- the `{timestamp}` path parameter
- market fields such as `start_time`, `end_time`, and `resolved_at`
- snapshot `time`
- timestamps inside error details

v4 does not accept or return ISO-8601 timestamp strings.

```bash
curl "https://api.polybacktest.com/v4/markets/1051520/snapshots?coin=btc&start_time=1777593600000&end_time=1777679999000" \
  -H "X-API-Key: $POLY_KEY"
```

<Info>
History is plan-limited. If `start_time` is omitted, the API starts at the oldest timestamp your plan can access: 31 days by default, or 60 days with the extended-history Pro add-on or a Dedicated/Enterprise plan.
</Info>

## Pagination

v4 uses `limit` and `offset`.

| Parameter | Default | Maximum | Description |
| :-- | :-- | :-- | :-- |
| `limit` | 50 for markets, 100 for snapshots | 100 for markets, 1000 for snapshots | Maximum records returned on this page. |
| `offset` | 0 | - | Number of matching records to skip. |
| `include_total` | `true` | - | Set `false` to skip the exact total count. |

List responses keep the v2-style named array and add a few explicit paging helpers:

```json
{
  "snapshots": [
    { "id": 551, "market_id": "1051520", "time": 1777593600123 }
  ],
  "total": 2480,
  "limit": 100,
  "offset": 0,
  "count": 100,
  "has_more": true,
  "next_offset": 100
}
```

When `include_total=false`, `total` is `null`; use `has_more` and `next_offset` to continue.

### Python pagination loop

```python
import requests

url = "https://api.polybacktest.com/v4/markets/1051520/snapshots"
headers = {"X-API-Key": "YOUR_API_KEY"}
offset = 0
all_snapshots = []

while True:
    body = requests.get(
        url,
        headers=headers,
        params={
            "coin": "btc",
            "limit": 1000,
            "offset": offset,
            "include_total": "false",
        },
        timeout=30,
    ).json()
    all_snapshots.extend(body["snapshots"])

    if not body["has_more"]:
        break
    offset = body["next_offset"]

print(f"Fetched {len(all_snapshots)} snapshots")
```

## Best practices

### Bound historical queries

For backfills, send explicit `start_time` and `end_time` values and use the maximum practical `limit`. For live polling, move `start_time` forward using the last record's millisecond timestamp.

### Request order books only when needed

Snapshot endpoints default to `include_orderbook=false`. Set it to `true` only for liquidity or order-flow analysis because full books make responses substantially larger.

### Skip totals when you do not display them

Exact counts add database work. Use `include_total=false` for streaming imports and infinite-scroll interfaces.

### Send individual requests

API v4 intentionally has no batch endpoint. Each request has one resource, one status code, and one error body.
